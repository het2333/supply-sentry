证据范围：`https://navisight.ai/`、`https://app.navisight.ai/` 的公开 HTML、CSS、前端静态包与公开截图资产。本文只记录可复核的视觉/信息架构事实；静态包中的演示数字不作为真实业务数据。

## 3. 已公开验证的信息架构与页面骨架

1. Overview
   - 6 张 KPI 卡；桌面视口使用三列到六列网格。
   - PO 表 + 右侧 AI Procurement Summary，宽屏右侧约 320–340px。
   - PO 搜索及 Route、Material Type、Stage、Risk、Supplier 过滤。
2. Notifications
   - 单列通知页；All / Unread、Mark all read、严重度、时间、对象摘要。
3. Drafted Emails
   - 左侧约 340–380px 队列，右侧邮件正文/上下文；Pending / All。
4. Local / Import
   - 共用采购路线工作台；KPI、风险圆环、阶段 tabs、PO 表和导出。
5. Risk Dashboard
   - 页头面包屑、日期、5 KPI、风险分布/拆解/供应商/账龄/产品/趋势。
6. Suppliers
   - 独立供应商页；从供应商进入对应路线的 PO 集合。
7. SLA / Advanced SLA
   - SLA 与 Advanced SLA 是两个独立导航项；Advanced SLA 明确包含按 section、manual 或 CSV 配置与 Auto-send follow-ups 开关。
   - 公开静态包可验证 9 个规则分区：Production / Service Milestones、Communication and Escalation Rules、Payment Term Rules、Logistics Planning Rules、Logistics Handover Requirements、Transit Monitoring Rules、Regulatory and Import Approval Rules、Customs Clearance Rules、Quality Inspection and GRN Rules。
   - 静态包中的 ACME、固定供应商、固定规则行属于演示样本；它们证明字段与页面分区，不证明持久化或客户数据。
8. Configuration
   - 独立配置页。
9. PO Detail
   - 固定页签：Overview、Items、Supplier、Documents、History、Communication。
   - 面包屑：Overview → Purchase Orders / Route → PO Number。

## 6. 对齐验收方法

- 每页至少验收 1280×720、1440×900 和 1920×1080 三个桌面宽度。小于 1024px 的手机/平板布局不属于当前 V1 验收。
- 浏览器截图只用于视觉比对；数字、状态和对象必须来自 Readywork API / SQLite。
- 正常、空、错误、无权限、连接器未就绪五种状态都要验收。
- 任何外部动作只有连接器回执成功后才允许显示成功；视觉按钮不能改变业务门禁。
- 不复制 Navisight 无登录 API 的暴露行为；Readywork 生产模式必须默认拒绝并保持租户/对象级授权。
