# Readywork 采购执行 V1 范围与验收契约

> 本文是 Readywork 采购产品 V1 的单一产品口径。V1 以 Navisight 公开可验证的“PO 发出后到 GRN”采购执行能力为基线，不把页面外观、测试数据、Mock 连接器或本地成功当作真实业务完成。

逐页功能、视觉、数据合同与发布验收矩阵见 `NAVISIGHT-V1-ALIGNMENT.md`。本文决定 V1 边界；矩阵决定边界内每个页面和阶段怎样才算完成。

## 1. V1 产品定位

Readywork V1 是采购订单执行控制塔，不是全套 Source-to-Pay。

```text
ERP / 已批准 PO
或邮箱 PO 附件 → 安全扫描 → 解析 → 人工核验
        ↓
PO Sent → Supplier Commitment → Fulfilment / Production
        → Dispatch / Transit → Delivery / GRN
        ↓
SLA 检查 → 自动跟进 → 风险与升级 → 人工决策
        ↓
供应商沟通 + ERP 核验 + 审计时间线
```

核心价值：采购人员不再人工追踪每张 PO；系统按阶段 SLA 持续执行，人只处理草稿审核、异常、升级和高风险决策。

### V1 基线冻结决定（2026-08-28）

- 产品能力与信息架构以 Navisight 公开、可验证的 `PO Sent → Supplier Commitment → Fulfilment / Production → Dispatch / Transit → Delivery / GRN` 为对齐基线。
- 视觉吸收其已公开验证的侧栏、圆角白卡、淡灰工作区、KPI、风险表格、进度和蓝色主色；没有公开截图的页面只继承视觉语法，不宣称未知页面的像素级复刻。
- V1 的发布判断只看真实 API、SQLite、状态机、策略、连接器结果、权限与审计；静态截图、Mock、演示字段和前端假成功均不计入完成度。
- Navisight 官网明确允许不先连 ERP、从邮箱开始；因此 V1 同时支持 ERP PO 和邮箱 PO Intake。邮件附件只能经过 MIME 限额与文件名清理、内容类型检查、ClamAV、文档解析和人工逐行核验后形成 PO。
- Navisight 公开 FAQ 明确供应商看到的是采购团队中的具名专业联系人，而不是 AI 身份；因此 V1 将“联系人姓名 + 职位 + 公司”作为所有外发采购沟通的强制、版本化、可审计门禁。
- RFQ、寻源、发票与应付继续保留为平台扩展能力，但不进入采购执行 V1 的上线验收范围。

### 公开产品入口与 Demo 申请（2026-08-31）

- `/product` 是 Navisight 采购执行 Employee Pack 的公开说明页，不是另一个采购业务前端，也不改变 `/` 工作台的登录、租户和 RBAC 边界。
- 公开文案可以解释 V1 目标、五阶段、人在回路、风险上下文和可连接系统，但不能把 readiness 未通过的具名身份、正式 SLA、真实路线或真实五阶段闭环描述为当前已上线事实。
- Demo 申请是独立的公开获客数据，不属于任何采购租户或 PO。它必须经过严格校验、幂等写入和追加审计；页面只能在后端事务成功后显示成功，不自动触发邮件、CRM、ERP 或采购工作流。
- 正式 Privacy / Terms 必须等待经批准的法律文本；官网空锚点不构成可复制的法律页面证据。
- 桌面公开页已补齐 `problem / gap / solution / how-it-works / risk-visibility / value / why-us / faq / demo` 完整叙事链；视觉示意不写入采购数据库，不引用对方客户指标或商标背书。
- 页面中“Odoo / Email / SMTP·IMAP / ERP adapters”只表达已存在的连接边界；WhatsApp 未配置时不在公开页宣称已上线。
- V1 当前只开发和验收桌面 Web，固定视口为 1280×720、1440×900、1920×1080。手机导航、移动抽屉、底部操作栏、触屏专用交互与小屏重排全部延期，不进入本轮实现、完成率或发布门槛；已有安全回退可保留，但不投入像素对齐。

## 2. 起点、终点和边界

### 起点

V1 有两个合法起点：

1. ERP 中已批准、已发出或待发出的 PO 及 PO 行进入 Readywork。
2. 邮箱中的 PO 附件经安全扫描、文档解析和人工核验后，生成尚未对外发送的真实 PO 草稿。

两条入口都必须保留源系统 / 邮件、外部 ID、版本、供应商、币种、金额、数量和 RIHD（Required In-House Date）。邮箱模式不等于自动信任附件；未经人工确认的解析结果不得进入正式 PO 状态机。

### 正常终点

- 本地采购：供应商履约完成，ERP 收货 / GRN 与 PO 行数量一致，审计链完整。
- 进口采购：除 GRN 外，发运、在途、清关和必需单证已校验。

“已生成邮件”、“已入 Outbox”、“本地已更新”都不是业务终点。只有外部连接器明确成功，才能标记已发送或已回写。

### V1 不作为上线门槛的能力

- 采购需求、寻源、RFQ、报价比较和定标。
- 发票、三单匹配、应付审批和付款。
- 供应商准入、合同全生命周期、招投标和自动谈判。

上述能力可以继续存在于 Readywork 平台，但不得影响 V1 信息架构和验收结论。

## 4. 五阶段状态机

```text
PO Sent
  → Supplier Commitment
  → Fulfilment / Production
  → Dispatch / Transit
  → Delivery / GRN
```

每个阶段都必须保留：

- 进入阶段时间、目标时间、宽限期和当前 SLA 状态。
- 原始证据、供应商回复、最新承诺和人工覆盖。
- 下一次自动检查、下一次跟进和升级时间。

阶段不能由前端猜测并回写。迁移必须由持久化业务事实触发，并带预期版本、操作者、时间和证据。

## 5. 路线模型

- `local`：本地 / 国内采购。
- `import`：进口 / 跨境采购。
- `unclassified`：源系统未提供路线。

系统只能根据明确的 ERP / PO 路线字段，或采购经理带依据的持久化人工确认进行分类。供应商名称、城市、语言和国家本身均不能替代交易路线证据；没有证据时必须返回 `unclassified`，不得为了填满仪表盘而猜测。

合同或 Incoterm 文件作为路线依据时，必须绑定当前 PO 并通过统一附件安全链。只有当前有效版本满足 ClamAV `clean`、文档解析完成、SHA-256 与附件版本可验证时才可确认路线；业务编号文本本身不是证据。已经在当前 PO 附件链中通过安全扫描与解析的文件可以原地绑定，但必须冻结当时版本和 SHA-256。错误证据的撤销必须带 configure 权限、原因、预期版本、幂等与追加审计；若路线依赖该文件，必须在同一事务内退回 `unclassified`。人工复核仍可使用独立核验 / 审批记录，但必须明确记录操作者、原因、PO 版本和追加审计。

## 6. SLA 和自动跟进

SLA 策略以“路线 + 阶段 + 风险等级”为匹配维度，至少包含：

- 首次供应商确认期限。
- 无回复跟进间隔和最大次数。
- 生产 / 备货进度检查间隔。
- 发运、在途和 RIHD 风险窗口。
- 宽限期、升级级别和接收角色。

AI 可以生成沟通草稿，但必须保存命中规则、PO 证据和当时的专业采购联系人身份快照。未配置身份时禁止生成；旧草稿缺身份快照时禁止批准；未经批准不能进入外部发送队列；高信任自动发送必须使用独立、可审计的策略开关。

## 7. 沟通和外部副作用

### Email

```text
SLA 命中
  → 持久化草稿
  → 人工编辑 / 批准 / 丢弃
  → 持久化 Outbox
  → 租约、幂等、超时与重试
  → 邮箱连接器明确成功
  → sent 事实
```

占位域名（例如 `example.com`、`demo.cn`、`.test`）不得进入真实发送链。

### WhatsApp

WhatsApp 必须使用真实 Business API 连接器、经验证凭据和模板状态。未配置时 UI 只能显示“未配置”，不能模拟已送达。

## 8. 风险与摘要

风险必须是可解释读模型，至少包含：

- PO 高 / 中 / 低风险和触发证据。
- 供应商维度的无回复、SLA 违约和交付表现。
- 按币种的在险金额，不在没有汇率快照时盲目加总。
- 逾期账龄区间、路线分布和风险历史快照。
- AI Procurement Summary 中的每个结论都可跳转到真实 PO 或风险集合。

## 9. 权限、审计和安全

- 读取、操作、审批、配置和管理员权限独立。
- 采购专员可编辑草稿，但无审批权时不能“批准并发送”。
- 每个状态迁移保存 actor、时间、版本、证据和结果。
- 凭据必须加密存储，API、错误、日志和前端响应不得泄露密码、授权码或 API Key。
- Outbox、连接器、租约、终态失败和安全事件进入生产监控。

## 10. V1 上线验收

1. 从真实 ERP 同步一张本地 PO 和一张进口 PO，路线与五阶段可在刷新和重启后恢复。
2. 供应商未确认或违反阶段 SLA 时，生成唯一、可解释的邮件草稿。
3. 编辑后刷新不丢失；版本冲突返回 409；丢弃和审批都有审计记录。
4. “批准并发送”只入持久化 Outbox；连接器未就绪时安全阻断；真实成功后才标记 sent。
5. 真实供应商回复能按邮件线程 / PO 关联，推进承诺阶段并重算 SLA。
6. 发运、部分发货、在途和 GRN 能按 PO 行累计，重复事件不重复计数。
7. 本地 / 进口页不得猜测路线；进口单证缺失会阻止完成并生成风险。
8. 风险看板能从快照重建趋势，金额按币种展示，摘要可追溯。
9. 通知已读状态、SLA 配置、路线映射和连接器状态全部持久化。
10. 断电 / 重启后任务、草稿、Outbox、通知、风险快照和审计链均可恢复，不重复发信或回写 ERP。
11. 邮箱 PO Intake 对 UID / Message-ID 和附件幂等；危险、超限、ClamAV 未通过或未完成解析的附件不能生成 PO。接受时必须人工确认供应商、币种、日期和每一行，且不发邮件、不回写 ERP。
